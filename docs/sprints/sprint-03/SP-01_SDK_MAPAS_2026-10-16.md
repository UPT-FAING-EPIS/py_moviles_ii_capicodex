## 1. Objetivo

Evaluar las alternativas de SDK de mapas disponibles para Flutter, analizar sus costos reales, restricciones de uso y consideraciones de privacidad y seguridad, a fin de confirmar o ajustar la elección actual del proyecto (**`google_maps_flutter`**) antes de desarrollar las funcionalidades de geolocalización en Sprint 3.

---

## 2. Alternativas evaluadas

Se evaluaron tres familias de SDK compatibles con Flutter:

| # | SDK / Paquete Flutter | Proveedor | Modelo de precio |
|---|---|---|---|
| 1 | `google_maps_flutter` ^2.5.0 | Google Maps Platform | Pay-as-you-go por SKU |
| 2 | `mapbox_maps_flutter` | Mapbox | MAU (Monthly Active Users) + API |
| 3 | `flutter_map` + OpenStreetMap | OSM / Stadia Maps / Jawg | Código libre; tiles de pago opcional |

## 3. Análisis de costo por opción

### 3.1 Google Maps Platform (`google_maps_flutter`)

Google cobra por **SKU** (unidad de uso individualizada). Los precios vigentes (2024-2025) son:

#### Maps SDK for Android / iOS (renderizado nativo del mapa)
- **Costo del mapa en sí: $0 (gratuito ilimitado)** para Android e iOS nativos.
- El SDK móvil nativo **no cobra por cargas de mapa**.

#### APIs auxiliares necesarias para GameOn Network

| SKU | Descripción | Capa gratuita | Precio tras límite |
|---|---|---|---|
| Geocoding | Dirección → coordenada o coordenada → dirección | 10 000 req/mes | $5.00 / 1 000 req (10k–100k) |
| Geolocator (device GPS) | Proveedor del dispositivo vía `geolocator` | **Sin costo** (local) | — |
| Maps JavaScript API (web) | Solo si la app se publica en Flutter Web | 10 000 cargas/mes | $7.00 / 1 000 cargas |
| Places – Autocomplete | Búsqueda con sugerencias | 0 req gratuitas | ~$2.83 / 1 000 req |
| Places – Nearby Search | Buscar lugares cercanos | 0 req gratuitas | ~$3.20 / 1 000 req |
| Static Maps | Imágenes estáticas del mapa | 10 000 / mes | $2.00 / 1 000 |

> **Nota:** El proyecto **NO usa Places API** actualmente. Las coordenadas de las instituciones se almacenan en la base de datos (Supabase), por lo que el único coste real en producción sería Geocoding si se necesitara conversión de texto a coordenadas. El GPS del dispositivo (`geolocator`) es **gratuito**.

#### Estimación de costo mensual para GameOn Network (escenario realista)

| Escenario | Usuarios activos | Llamadas Geocoding estimadas | Costo mensual estimado |
|---|---|---|---|
| MVP / prueba (Sprint 3) | < 50 | < 200 | **$0** (dentro del tier gratuito) |
| Beta cerrada | < 500 | < 2 000 | **$0** (dentro del tier gratuito) |
| Producción inicial Tacna | < 5 000 | < 8 000 | **$0** (dentro del tier gratuito de 10 000) |
| Crecimiento moderado | 10 000 | ~15 000 | **~$0.25 USD/mes** |

**Conclusión Google Maps:** Para el contexto actual del proyecto (app educativa, usuarios limitados, región de Tacna), el costo es **$0 en práctica**, siempre que no se activen Places API ni búsquedas de texto geocodificadas masivas.

### 3.2 Mapbox (`mapbox_maps_flutter`)

- **Modelo:** Facturación por MAU (Monthly Active Users).
- **Tier gratuito:** 25 000 MAU/mes gratuitos.
- **Precio tras límite:** ~$5.00 / 1 000 MAU adicionales.
- **APIs auxiliares:** 50 000–100 000 req/mes gratis para Geocoding y Directions.

**Ventajas:** mayor control de estilo visual, buenas capacidades offline.  
**Desventajas:** requiere migración completa del código, no está integrado actualmente, licencia más restrictiva para redistribución.

---

### 3.3 OpenStreetMap con `flutter_map`

- **Costo del paquete:** $0 (MIT License).
- **Costo de tiles:** depende del proveedor:
  - OSM Foundation (uso directo): solo para desarrollo, **prohíbe** uso en producción sin contribución/acuerdo.
  - Stadia Maps: 200 000 tiles/mes gratis, luego $20–$100/mes según volumen.
  - Jawg Maps: 50 000 tiles/mes gratis.
- **Ventajas:** código abierto, sin tarjeta de crédito requerida.
- **Desventajas:** calidad de datos POI inferior, requiere integración manual de geocoding (Nominatim/Pelias), sin soporte de tráfico en tiempo real.

## 5. SDK elegido: `google_maps_flutter`

### Justificación

1. **Ya está integrado** (`pubspec.yaml` línea 20: `google_maps_flutter: ^2.5.0`), con API key configurada en `AndroidManifest.xml` y widgets funcionales en `mapa_instituciones_view.dart`.
2. **Costo $0** para el volumen de usuarios esperado en el sprint y en la beta del proyecto.
3. **`geolocator`** (ya integrado) provee la posición GPS del dispositivo de forma completamente gratuita.
4. **Calidad de datos en Tacna, Perú:** Google Maps tiene cobertura superior a OSM en la región.
5. **Riesgo de migración innecesario:** cambiar a Mapbox u OSM requeriría refactorizar `mapa_instituciones_view.dart` completo sin ganancia real en este sprint.

### Restricciones identificadas

| Restricción | Detalle |
|---|---|
| Requiere API key activa con billing habilitado | La cuenta de Google Cloud debe tener billing activado; sin tarjeta, el mapa muestra "For development purposes only" |
| API key embebida en el APK | Riesgo de exposición si el APK es descompilado |
| Places API no está incluida | Si en el futuro se agrega búsqueda por texto, se facturará por separado |
| ACCESS_BACKGROUND_LOCATION | El `AndroidManifest.xml` actual declara este permiso; se debe revisar si es realmente necesario (Google Play exige justificación) |
| Clave hardcodeada en AndroidManifest.xml | Ver sección de seguridad |

## 6. Consideraciones de privacidad y seguridad

### Dato personal: ubicación
- La app solicita `ACCESS_FINE_LOCATION` y `ACCESS_COARSE_LOCATION` para centrar el mapa en la posición del usuario.
- La ubicación **no se almacena en servidor**; se usa solo en memoria para centrar el mapa y calcular distancias locales.
- `ACCESS_BACKGROUND_LOCATION` declarado en el manifest **debería eliminarse** si no se rastrea la posición en segundo plano, para cumplir con las políticas de Google Play y minimizar datos personales.

### Clave de API
- La clave actual está **embebida en texto plano** en `AndroidManifest.xml`.
- **Acciones requeridas para producción:**
  1. Restringir la clave en Google Cloud Console → sólo para el package name de la app + SHA-1.
  2. Activar alertas de presupuesto en Google Cloud Billing (umbral: $1 USD/mes).
  3. No agregar la clave al historial de Git si se rota; usar variables de entorno o Flutter `--dart-define`.

## 7. Prueba mínima funcional (Proof of Concept)

El proyecto ya cuenta con una implementación funcional en `mapa_instituciones_view.dart` que valida:

- Renderizado del mapa de Google en pantalla.
- Obtención de la posición GPS del dispositivo vía `Geolocator.getCurrentPosition()`.
- Creación de marcadores `Marker` para cada institución deportiva.
- Animación de cámara hacia la ubicación actual del usuario.
- Interacción con marcadores (tap → muestra panel de detalle de institución).
- Manejo de permisos de ubicación denegados con fallback visual.

### Fragmento de código del PoC existente

```dart
// mapa_instituciones_view.dart — integración real en el proyecto
import 'package:google_maps_flutter/google_maps_flutter.dart';
import 'package:geolocator/geolocator.dart';

// Obtener posición actual
Position position = await Geolocator.getCurrentPosition(
  desiredAccuracy: LocationAccuracy.high,
  timeLimit: const Duration(seconds: 10),
);

// Centrar mapa en posición del usuario
_controller?.animateCamera(
  CameraUpdate.newLatLng(LatLng(position.latitude, position.longitude)),
);

// Marcadores para instituciones deportivas
final marker = Marker(
  markerId: MarkerId(institucion.id.toString()),
  position: LatLng(institucion.latitud, institucion.longitud),
  onTap: () => setState(() => _selectedInstitucion = institucion),
);
```

La prueba se ejecutó visualmente en el emulador Android (API 33) sin errores de compilación ni de runtime.

## 8. Conclusiones y recomendaciones

1. **SDK elegido: `google_maps_flutter` v2.5.0** — ya integrado, estable y sin costo para el volumen del proyecto.
2. **Costo proyectado: $0 USD/mes** durante todo el ciclo de vida del proyecto académico y beta.
3. **Riesgo principal: seguridad de la API key** — se debe restringir la clave en Google Cloud Console antes del primer release público.
4. **Permiso `ACCESS_BACKGROUND_LOCATION`** debe eliminarse del `AndroidManifest.xml` si no se usa rastreo en segundo plano.
5. **No se recomienda migrar** a Mapbox ni a OSM en este sprint; el beneficio no justifica el costo de migración.
6. **Para el Sprint 3**, el equipo puede avanzar directamente con la épica de geolocalización usando la integración existente.
